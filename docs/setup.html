Set up Chain of Custody

Chain of Custody watches a platform's database from outside the platform. It seals every transaction, lets an independent witness check the seals, and reports anything that was changed. Three tracks, in order:

1 · Try it

Run the whole product on one laptop and attack it. 10 minutes.

Go

1 · Try it on one laptop

You need Docker Desktop running, and Python 3.11+.

git clone https://github.com/JeevikaS-19/cybersec.git
cd cybersec
python docker/ctl.py up

Open http://127.0.0.1:8000/. Everything should be green within about 10 seconds.

Done when: the page shows Connected with all three checks green.

Then attack it:

python docker/ctl.py intruder       # edits the log over SSH, Layer 1 catches it
python docker/ctl.py tamper-record # changes a transaction in the bank database, Layer 2 catches it
python docker/ctl.py cut           # unplugs the server; after 45 s it quarantines itself
python docker/ctl.py restore       # plug it back in; two key holders unlock it
python docker/ctl.py reset         # start again from scratch

2 · Connect your platform

You need: a PostgreSQL or SQLite database with a transactions table and an accounts table, and a Linux server (or VM) where the platform runs. Nothing in your application code changes.

Step 1 · Read-only database user

CREATE ROLE coc_reader LOGIN PASSWORD '<a strong password>';
GRANT SELECT ON transactions, accounts TO coc_reader;
Done when: SELECT has_table_privilege('coc_reader','transactions','UPDATE'); returns f.

Step 2 · Describe your tables

Copy config/platform.yaml and change the names to yours. Amounts are whole paise, or decimal rupees with amount_unit: rupees. The password is never written in this file; it comes from an environment variable.

KeyWhat it means
transactions.table, columns.row_idYour table, and an increasing id column
columns.from_account, to_accountAccount columns. A NULL side means money from or to outside (deposit, withdrawal)
columns.amount, amount_unitThe amount column and its unit (paise or rupees)
columns.from_balance, to_balanceOptional: balances after each transaction, if your table stores them
whereOptional filter, e.g. status = 'completed'
accounts.table, id, balanceYour accounts table and its balance column
Done when: the agent starts without platform source unavailable in its log.

Step 3 · Install the agent on the platform server

sudo COC_PLATFORM_CONFIG=/opt/coc/config/platform.yaml \
     WITNESS_URL=https://<your witness address> \
     COC_DB_DSN='postgresql://coc_reader:<password>@127.0.0.1:5432/<database>' \
     COC_PROTECTED_PATH=/var/log/<your-app> COC_L3_DRY_RUN=1 \
     bash deploy/install-log-server.sh

Then register the profile-id your admins will use with guarded commands (stored only as a hash):

sudo bash -c 'cd /opt/coc && PYTHONPATH=/opt/coc venv/bin/python -m layers.l1_tripwire.profiles add <platform name>'

Keep COC_L3_DRY_RUN=1 until you finish Step 5.

Done when: systemctl is-active coc-agent coc-backstop prints active twice.

Step 4 · Witness

Run the witness on its own server (never the platform server), or use one you were given:

sudo PORT=8810 PREFIX=/custody bash deploy/install-witness.sh

Put it behind your HTTPS address. Then hand one key-holder share to each of three people and delete the files from the server.

Done when: https://<your witness address>/custody/ shows the auditor view with Connected.

Step 5 · Test one transaction

  1. Make a deposit or transfer in your platform.
  2. Watch the auditor view: the records-verified count goes up, and no alert appears.
  3. Make a reversible test change on one demo row (ask your witness owner for the steps). The page must show the record in red within about 15 seconds. Put the value back.
Done when: the honest transaction shows as verified and the test change is caught.

3 · Turn on Stop (optional)

Read before you start. Stop locks every login account on the server, root included, ends their sessions, and stops your application if the witness is unreachable for 45 seconds. A network blip can lock out the people who need to fix it. Only turn this on after you have a recovery path that does not use the network (for example a hypervisor console or a break-glass account kept offline).
  1. Recovery first. Write down and test how you get back in with no network. Do not continue until you have done this.
  2. Set the stop and start commands for your application in layer3 of config/layers.yaml, e.g. stopping your frontend container.
  3. Trial run. Keep dry_run: true. Cut the network for 50 seconds and check the page shows what would happen.
  4. Switch it on on a test copy of the server first, then on the real server, by reinstalling with COC_L3_DRY_RUN=0.
Done when: a planned cut locks the test accounts, and two key holders can unlock them and get back in.

If something goes wrong

SymptomCheck
Agent says platform source unavailableThe DSN in /etc/coc/coc.env, and that the coc_reader role can connect
Witness shows no recordsWITNESS_URL in /etc/coc/coc.env, and the proxy path (/custody)
Honest transactions raise alertsThe platform writes the balance and the transaction separately; the witness re-checks before alerting. Confirm the transaction row exists before reporting.
Admin edits show as intruderThe admin must use the profile-id: nano --<profile-id> file

Undo everything

sudo systemctl disable --now coc-agent coc-backstop
sudo rm -rf /opt/coc /opt/trip /etc/coc /var/lib/coc /var/spool/coc /etc/systemd/system/coc-*.service /etc/profile.d/coc-*.sh
sudo systemctl daemon-reload

Then drop the coc_reader role from the database.
